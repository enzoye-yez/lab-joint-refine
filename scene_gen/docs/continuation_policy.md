# 局部失败后的持续推进

本轮调整面向静态场景生成：先处理局部失败，再继续其他有依据的工作。复用现有请求入口、审查会话、检查收据与修复调度，没有另外建立一套调度框架。原数值检查器、公差和实验资产不变。

## 现在如何处理原来的停止条件

| 情况 | 新行为 | 保留的结果 |
|---|---|---|
| 再次读取以前看过的详情页 | 重新核对归档摘要，返回已有内容；允许比较不同页 | 原文、来源和全部调用仍在 |
| 详情读取连续没有新增可用内容 | 窗口结束先提示整理并提交结论；继续无效读取才暂挂当前任务 | 未解决事项保持未知；独立资产和已确认缺陷仍可继续 |
| 读错路径、页内容过大 | 把具体错误交回当前请求，允许缩小路径或分页 | 不吞掉原要求、不截断必要源码 |
| 审查格式反复无效 | 保留合法事项；场景多事项任务进一步拆成单项审查 | 某一项失败不丢弃其他项的有效答案 |
| 一个资产的审查上下文无法处理 | 暂挂该资产审查，继续其他资产及场景检查 | 不把未知写成通过 |
| 补查达到原轮数 | 改为进展窗口；窗口内有新的成功观察时继续 | 无效动作窗口、相同动作收据和总预算仍有效 |
| 补查模型声称没有能力 | 先尝试注册能力给出的未执行合法动作；没有替代动作时要求重新核对 | 不能靠一句声明立即终止整场，也不能凭空制造能力 |
| 修复方案无效或声称阻塞 | 联合范围尝试后缩小到单个受影响资产；重复阻塞让出当前范围 | 保存所有拒绝原因和实际采用方案 |
| 部分资产不可加载或缺失 | 发布并检查已有部分，修复其中已定位的问题 | 缺件保持明确标记，不冒充完整交付 |
| 修复导致场景无法装配 | 恢复之前可加载基线，再请求不同方案 | 失败候选、阶段、消耗均保留 |
| 首次装配失败但已有可信定位 | 将已定位装配缺陷送入现有修复入口 | 没有可靠定位的执行错误不作为几何修改理由 |
| 临时资产检查故障 | 使用原收据，在有限重试次数内重试同一动作 | 成功后旧错误转入历史，不继续污染当前状态 |
| 中断 | 复用已付费响应和已完成检查；未返回的审查不消耗格式纠错次数 | 不重置调用、令牌或累计资产迭代 |

`max_context_reads`（详情无进展窗口，默认8）不再是详情总读取次数上限。返回旧页本身不会立即停止。
`max_evidence_rounds`（补查进展窗口，默认6）不再无条件结束仍在取得新观察的审查。
`max_repair_plan_attempts`（每个修复范围的方案尝试上限，默认5）先约束联合范围，再约束各个局部范围；它不再表示整个场景只能尝试五个方案。
审查格式仍采用三次纠错，随后缩小事项范围或暂挂任务，不无限重放同一错误。

场景总迭代与每个资产累计生成迭代仍按用户给定配置执行；依赖变化和恢复不会清零累计消耗。读详情、纠错、缩小任务和替代方案都使用同一个模型调用与令牌账本。拆分会增加固定请求开销，目前没有正式成本下降结论。

## 哪些情况仍会结束本次执行

- 用户暂停或中断。
- 全局模型调用或令牌额度耗尽，以及配置的累计场景迭代额度耗尽。
- 服务鉴权、余额、参数等实际阻塞；临时网络故障沿用已有重试与冷却策略，结果未知请求仍须显式恢复。
- 实现、归档或只读证据发生不一致；无法持久保存状态等全局执行故障。
- 当前任务的整理、纠正、缩小范围或既有能力均不能产生下一步，且没有其他可执行工作。此时保留最好场景与具体未解决项，不报告验收成功。

没有取消加载约束、验收条件或实际能力边界。没有新增通用几何求解器，也不保证任意模型响应都能被修成正确场景。本轮持续推进与候选保护重点覆盖静态流程，不声称完整操作仿真也具备同样路径。

## 两轮工程审查

第一轮检查提示、校验约定及异常路径：

- 详情协议明确允许重读，失败返回可执行的路径/分页反馈。
- 多事项审查仍按完整约定合并；框架只能补“未解决”，不能补“已解决”。
- 修复范围只包含已有源码及可加载候选；模型的阻塞声明转成方案反馈。
- 临时检查成功后移除当前错误，原错误保留在历史；不可用清单形成当前审查的能力缺口。

第二轮检查证据、预算和中断恢复：

- 重读仍校验归档摘要，证据绑定仍包含几何、要求、布局、实现与契约。
- 新旧候选选择不回退消耗；相同无效修复不能靠改写原因再次执行。
- 补查进展从保存的实际观察计算，中断恢复不会漏掉刚完成的观察。
- 审查尝试与结果一起提交，未返回的中断不占用格式纠错次数。
- 保留用户暂停、未知请求、过期证据、路径越界及总预算的既有回归。
