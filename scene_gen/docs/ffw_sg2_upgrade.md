# FFW-SG2 双臂整机接入与验证

本轮在现有生成、装配、审查、修复和恢复流程中升级机器人接口，未另建一套代理。默认整机为 ROBOTIS AI Worker FFW-SG2（乐博思双臂移动机器人）；TIAGo OMNI（单臂全向移动机器人）保留在 `config/scene_environment_tiago.json`。

## 来源及适配

- 厂商模型：[固定提交](https://github.com/ROBOTIS-GIT/robotis_mujoco_menagerie/tree/d8344c0dbe7a00208d0301111523dde65efc174a/robotis_ffw)。本地 `data/robots/ffw_sg2` 保存原始模型、许可、全部网格、四个装配变体及 `provenance.json`（来源与文件摘要）。
- 原始自由根在派生模型中转换为世界原点下的平面 X/Y/偏航坐标；原始连杆位置、惯性、限位、轮组及夹爪联动保留。没有合成底座。
- 原始模型初始轮底离零平面 0.1465 米。派生资源保持原始坐标，场景装配明确下移 0.1465 米落地，并写入场景元数据。独立查看器相应升高显示地面。
- 每臂名义额定负载 3 千克；641 毫米用于粗略腕部距离建议；原厂夹爪名义质量约 0.5 千克。不是将双臂总负载或峰值能力分给单臂。参考[厂商硬件说明](https://ai.robotis.com/ai_worker/hardware_ai_worker.html)。
- 升降模型坐标为 -0.5 至 0 米；默认 -0.25 米。底盘包围盒来自固定模型，通道检查使用实际整机姿态几何而非仅用此参考尺寸。
- 原始腕部合并了部分夹爪惯性；去夹爪变体保留腕部惯性。因此换装模型可用于当前静态验收，不能据此认证精确动力学。

## 统一约定

`robot_contract.py`（机器人统一契约模块）将机器人表示为公共关节、机械臂清单和原厂末端。旧单臂输入在入口转换；运行各阶段通过同一组辅助函数使用接口。

计划逐臂声明 `end_effectors`（末端配置）：`stock`（保留原厂）、`adapter`（夹爪外壳固定适配件）或 `replace`（腕部替换）。两只原厂夹爪足够时不创建工具任务。定制实例必须唯一绑定实际安装点，记录理由；固定外壳适配点不会假装随夹指运动。

替换一侧时移除该侧夹爪几何、关节、专属驱动、联动和引用，另一侧保留。缺失定制工具时发布已有部分，并标注缺件；不会偷偷恢复原厂夹爪。修复可以通过 `tool_additions`（新增工具任务）在已确认需要后新增定制总成。

关节数量不再限制为 16。请求只带实际关节类型、范围和联动摘要；不重复注入机器人源码。位置伺服初始化为对应位置，速度及力驱动初始化为零。从动指节由联动主关节推导。

## 检查与恢复

左右肩在底盘朝向及共享升降姿态下分别评估，并给出建议使用的手臂；不会要求每件仪器同时满足双手操作。通道包络包含整机与已安装工具。升降采样使用实际模型；带自由耦合工具时不虚构未同步的工具姿态，保留当前姿态建议。

逐臂计算原厂夹爪、定制总成和明确分配的工作负载。无法分配到具体手臂的标量负载记为待验证。刚性父子关系不能代替实体安装接合；定制总成远离选定腕部或夹爪时会产生安装缺陷。

安装选择和机器人姿态加入布局版本及证据身份。改动后拒绝旧证据；候选回退恢复计划、安装配置、任务顺序和已发布场景，累计调用与候选尝试保留。上下文仍使用当前状态、接口摘要、引用和分页；不扩大上下文保护上限。

## 两轮审查及修复记录

第一轮检查提示、校验约定和异常路径，发现并修复：

1. 单工具假设散布于计划、装配和检查：改为逐臂声明；旧单臂缺失工具元数据仍按原约定反馈，避免兼容回归。
2. 姿态只检查数字而未检查实际限位和联动：规划、布局与修复入口统一使用模型关节摘要验证。
3. 仅保留原厂夹爪时可能跳过布局精修：全基础资产候选完成后仍进行现有布局精修。
4. 工具虽然挂在机器人运动树上却可能实体悬空：加入选定安装区域的实体接合检查。
5. 平面化后保留官方自由根初始高度会使轮底悬空：显式落地偏移并验证轮底接地。

第二轮检查证据、预算和恢复边界，发现并修复：

1. 新增工具后调度顺序、候选回退顺序可能不一致：按当前完整计划重建顺序，回退保留累计账本和尝试数。
2. 安装选择或姿态变化可能复用旧检查：两者纳入布局版本及补查身份。
3. 单侧定制失败容易隐式恢复原厂夹爪：变体选择依赖完整计划，缺件继续发布并注明未完成。
4. 共享升降采样与自由耦合工具可能不同步：保守使用当前构型并显式说明采样限制。

未增加“双臂能力不足就停止整轮”的门槛；不可达建议及未知事项交给现有审查与修复。用户暂停、共享预算和请求状态保留既有语义。

## 验证及能力边界

开发合成测试与正式模型生成分开。新增测试覆盖官方模型多个姿态的连杆、限位及惯性一致性，双臂及升降运动、夹爪联动、速度驱动零初始化、左右单侧适配和替换、双侧替换、重复安装、错误手臂、悬空附件、缺件发布、逐臂负载、整机通道包络、证据过期、新工具调度、预算暂停恢复及回退不退款。

针对性回归 39 项通过；最终双臂专项 14 项通过。第一次全量 778 项发现旧单臂缺失工具元数据回归，已修复。最终全量 **784 项测试全部通过，耗时 355.511 秒**。实现摘要为 `4be824a8aab2564aa6f58b892789a74acc72c1a77163fe0891510332b8ebb553`。完整结果见 `.cache/ffw_upgrade_20261020/full-tests-final.log` 和 `.cache/verification.json`（实现验证收据）为准。

静态加载与测试通过不等于正式场景质量通过。完整轮式导航、接触抓取成功、双臂协同轨迹、换装精确动力学未纳入验收。粗略可接近建议不能当作任务可执行的证明。交互查看器的运动学和分组数据已测试，界面未逐个滑块人工验收。
