# 移动场景架构修复（2026-10-20）

本次处理架构审查复现的七类问题。修改生成与审查框架，不修改已生成资产、原检查报告、验收公差、旧运行或正式调用账本。测试响应及资产均为开发者合成样例，没有调用正式模型服务。

## 修复行为

| 问题 | 根本修改 | 保留的边界 |
|---|---|---|
| 部分场景调整布局时访问不存在的任务状态 | 区分尚未生成任务与已有候选的复核任务；缺件继续由原调度器生成。候选另存完整请求计划，回退只恢复已发布候选，不删除未完成任务 | 不伪造工具或替代资产；回退不清零预算 |
| 单资产检查进程失败牵连整个场景 | 把可信的资产进程故障转换为统一故障范围，覆盖该资产全部实例与依赖后代；仍允许无关对象的已确认缺陷进入修复 | 程序错误、来源不明及全场景故障不被冒充局部错误；故障记录不变成通过 |
| 合法换摆放方式被认为丢失证据 | 装配完整性检查始终存在；桌面摆放改落地时，比较器同时核对前后计划和完整承托检查，明确记录检查义务转换 | 不把桌边检查消失称为修好；其他检查缺行、跳过或变未知仍拒绝退化候选 |
| 机器人及工作台不属于资产实例，无法提出合法修复 | 统一 `affected_layout`（受影响布局对象）与 `layout_review_targets`（合法布局对象清单），贯通审查、分批合并、问题身份及修复任务 | 布局权限不授予机器人或其他仪器几何修改权；未知编号仍拒绝 |
| 作者收到旧版固定桌面提示 | 作者提示与加工策略都从环境契约派生。移动模式采用工作台局部加工坐标，取消桌面中央机器人保护区；固定模式保持原规则 | 不缩放仪器，不把实际未声明凹槽当作已有条件 |
| 单任务携带整份资料及过大的依赖信息 | 任务输入只展开对应资产章节，并保留共享前言与一级、二级公共章节；规划仍读取完整目录。较长原文、规程及依赖信息以准确原文分页送达；计划的编号、姿态和数值契约保持可见 | 不用模型摘要替换原始要求；当前待修改代码和数值约束不盲目截断 |
| 图片总量阻断补查甚至阻断数值工具 | 图片归档与单次传输分离。图片按数量、上下文和请求字节限额分批送达；允许按清单索引重新对照。补查工具不再把历史图片数量当作执行资格 | 不删原图、不降分辨率、不改数值阈值；所有页面及重读仍计入同一账本 |

## 分页协议与证据边界

`max_images`（单次图片上限）限制一条模型请求，默认仍为 24；不再限制一个资产或一次审查能够保存的全部图片。补查产生的新图片进入原有归档，数值检查不受图片数量影响。

`context_delivery`（资料送达状态）列出当前页、剩余批次、原文页及全部图片编号。资料尚未送达完时，模型只需用 `context_notes`（工作笔记）保留重要要求与观察。若提前返回最终结果，框架归档该提议并继续送达剩余资料，不把它当成完整任务结果。此前图片页提出的修复缺陷会保留到最终阶段校验，不能被后页的接受结论静默覆盖。

`context_images`（图片对照读取）允许在本次任务清单内重读不同页的图片。`context_read`（只读资料分页）仍校验引用所属范围和内容摘要，字符串页最大 32,768 字符，实际页面还按字节限额缩小。重复原文可共用引用，但不同原文和不同像素不会被混合。

依赖接口的行列编码先还原再分页，避免把无损表格的行数组替换成引用后仍标为完整表格。原文、完整资料、分页回执、模型请求和每次图片清单均保留溯源。模型笔记和“已送达”记录不是检查通过的证明。

小份原文页按有界字节额度合并到同一批次，避免每份短依赖都产生一次请求。合并只改变批次划分，保留各页原引用、位置和完整内容。

单次保护边界仍是原有 922,000 工程估算额度，输出预留和余量不变。分页更省单次上下文，但不保证累计调用或总费用降低。单段不可拆的必要源码、单张原图本身超过可传输范围时，仍保留具体诊断，不能假装已处理。

## 两轮工程审查

第一轮：提示、校验约定、异常路径。

- 检查移动环境作者的真实请求，确认局部加工坐标与加工器一致。
- 将布局对象契约贯通一般审查、事项分批、单项恢复与修复调度，拒绝未知对象。
- 清除生成入口和补查规划器残留的图片总量门槛，而不只修改传输层。
- 校正大依赖表分页顺序，保留无损编码的合法结构。
- 明确区分可隔离的进程环境故障与检查器程序错误，保留独立问题修复路径。

第二轮：证据、预算、恢复边界。

- 发现并修复部分候选回退可能遗失完整计划的问题；发布身份同时绑定完整请求计划和已装配子集。
- 原文分页按确定顺序组织，恢复可重用相同请求缓存；不能因换页跳过未知请求。
- 分页、资料重读、图片对照使用相同调用与令牌账本；暂停和实现漂移检查仍在每次发送边界生效。
- 验证原文逐字还原、所有不同图片实际送达、单图字节超限发送前拒绝、故障后代隔离、缺件计划恢复及桌面转落地的反例。
- 未改变悬空、碰撞、槽位、规格、来源校验或过期证据的验收标准。
