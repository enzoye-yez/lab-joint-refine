# 完整场景生成与受限修复

只查看场景而暂不操作时，参见 [首次静态实验](static_preview.md)。`--static-only`（仅静态验证）保留静态检查与外观修复，跳过动力学、操作探测和可达性求解，结果明确标记为静态候选。

该入口实现：完整资料包 → 轻量任务及实例清单 → 仪器/配合组生成 → 统一末端装置与可选辅助固定装置 → 移动机器人和可变多工作台装配 → 独立检查与视觉审查 → 定向修复 → 场景和规划交接文件。

**评测直接读取已有资产清单、规格和图片，不调用资产提取或联网搜索。** `src/asset_prep`（资产准备模块）源码保持不变，仅复用公共配置、传输和账本。未来原始规程路线可先独立调用准备模块，再把其资料包交给此入口。

生成、修复、视觉审查均请求 GPUGeek（模型接口服务）的 `GPT-6-astra`（模型标识），沿用 `config/default.json`（服务配置）。不会自动换服务或模型；请求模型和响应模型分别记录。正式调用只由用户执行。

## 当前环境（移动布局）

完整契约及限制见[移动布局升级](mobile_layout_upgrade.md)。默认静态模式，只评估粗略通道和操作距离，不要求轨迹生成。

默认机器人为 TIAGo OMNI（单臂全向移动整机）：七关节手臂、0.35米升降行程、0.87米臂展和不含末端的3千克全伸展负载。厂家整机描述、固定版本、原厂夹爪与专用末端两种构型、转换及仿真近似见[整机接入说明](tiago_omni.md)。最大臂展不等于所有方向均可操作，末端装置质量计入负载。

`config/scene_environment.json`（环境配置）指定移动底盘及机械臂固定规格。模型在 `layout`（布局）中自主提出房间和多张桌子；旧 `table`（工作台）字段仅作为尺寸参考。落地仪器放在地面；托盘上的实例保留支撑关系，不永久焊接。`config/scene_environment_fixed.json`（固定环境配置）保留旧单桌方式。

## 运行

工作目录均为 `D:\harness\new_harness`。本机Python（编程语言）环境和公开 TIAGo OMNI 整机资源已经就绪，本地进程完整工程验证已通过。首次实验按[静态指南](static_preview.md)加 `--backend local`（本地后端），无需 Docker（容器运行工具）。正式服务请求仍由用户实验验证。

.\run.ps1 scene --prepare-robot

## 预算和停止条件

`config/scene.json`（场景配置）默认：全流程最多800次模型请求、240,000,000预留词元、80轮场景装配验收；单次场景修复最多修改3个资产任务，依赖失效引起的装置重新生成仍计入共享预算。生成、修复和全部视觉审查使用同一个调用账本。

`config/generation.json`（单资产配置）仍约束每项资产累计最多60次候选尝试（包括首次生成）、单次输出16,000令牌、每个资产任务原始参考图片上限24张及请求24,000,000字节。全场景原图逐资产完整分配。末端装置和辅助固定装置阶段使用每项已生成依赖的首个实际渲染视角、实测接口、完整规格和原图索引；原图及完整多视角证据留在前序资产版本。该视角选择明确写入请求和版本记录，不伪称此阶段重新审查了全部原图。依赖图片数量由任务总数限制，全部请求仍遵守字节及共享令牌上限。配合组原图数或请求字节超限时明确拒绝。

单资产产物最多64,000,000字节、128文件，工作进程120秒；场景产物最多256,000,000字节、2048文件，场景检查300秒。容器输出临时空间受限，归档拒绝链接、设备、路径穿越和不允许的文件类型。

令牌是保守工程估算，不是货币费用保证；图片逐张预留16,384令牌，返回后按预留与报告用量的较大者记账。默认预算较大，首次真实验证可主动压低：

```powershell
.\run.ps1 scene --package D:\harness\selected50_protocols\NP-001\asset_package.md --run scene_np001_small --execute --expected-implementation $verifiedImplementation --max-model-calls 12 --max-reserved-tokens 1200000 --max-iterations 2
```

该小预算可能在完成全部资产前暂停，这是预期行为。暂停后保留调用缓存和工作区，用户可显式提高预算恢复：

```powershell
.\run.ps1 scene --package D:\harness\selected50_protocols\NP-001\asset_package.md --run scene_np001_small --execute --expected-implementation $verifiedImplementation --resume --max-model-calls 800 --max-reserved-tokens 240000000 --max-iterations 80
```

未知结果请求只有核对服务商记录并接受重复计费风险后，才增加 `--retry-uncertain`（重试未知请求）。源码、资料、机器人、容器镜像或固定验收变更会使原运行身份失效，需要新运行，不能伪装成同一配置的恢复。

## 场景清单与修复范围

清单包含生成任务、实例、假设和移动布局：

- `layout`（布局）：房间、各工作台、移动机器人初始位置和停靠候选；桌面实例以 `table_id`（工作台编号）关联。

- `jobs`（生成任务）：编号、资料包资产编号、资产/末端装置/辅助固定装置角色、依赖、设计要求。每个资料资产恰好归入一个资产任务；强配合组件可联合生成。装置依赖实际资产版本，接收它们的交互清单和实测接口坐标。
- `instances`（物理实例）：实例编号、对应任务、桌面/地面/机器人安装面、世界位置、朝向，可选 `support_instance`（承托实例）。同一生成产物可多次实例化，框架为全部对象及资源加前缀，避免重名。
- `assumptions`（假设）：数量或布局推断及未确定事项，不把推断伪装成厂家事实。

每项任务维护自己的 `model.py`（建模脚本），无需学习自定义建模语言。末端装置可含主动机构；固定安装主体不带自由根关节，可拆部件作为独立世界根部自由刚体，经已声明的初始启用焊接约束连接到主体。必须提供 `tcp`（工具操作坐标）；机器人安装坐标由框架固定。最终装配使用MuJoCo（物理仿真引擎）的模型编辑接口，最终资源独立打包，可在新进程重新加载。

修复器不能修改资料包、机器人规格、房间边界、验收或未授权资产。移动模式允许调整工作台和机器人停靠位置，并携带桌上支撑链；旧固定模式仍只调整授权实例的位置和朝向；资产修复只接受当前脚本的唯一文本替换。修改资产后，其依赖装置失效；单纯移动仪器不会重生成无关资产。

版本归档后检查完整文件摘要。异常中断的工作区保留为废弃尝试，不自动删除，也不作为场景输入；缓存请求可在新工作区重放。修改已归档版本会使恢复停止。账本与多个文件不是跨断电数据库事务；未知现场保留，不尝试猜测恢复。

## 检查和分工

单资产检查：实际编译、语义引用、明确指定的几何尺寸/关节、初始接触、关节离散采样、短时数值检查、真实渲染和视觉比较。按钮由独立压头实际接触推动，连接释放必须由真实按钮事件或已声明软件接口触发。可逆连接重新接合还要求定位误差达标；不可逆连接禁止重新锁合。

场景检查：跨实例几何距离（包含静态对象）、机器人自接触、支撑面或支架接触、桌面边界、末端质量加已声明工作负载、配合尺寸、开盖时与邻居的碰撞、重力下自由物体明显位移、关键操作姿态及整场景视觉审查。

关键姿态使用有界、确定性重启的逆运动学搜索，并检查候选姿态碰撞。成功只证明找到某个离散姿态；失败也不证明数学上绝对不可达。没有指定目标姿态时，从操作接口推断30毫米接近偏移及接口朝向，并明确记录该假设。

后续轨迹模块负责连续路径、抓取/接触控制、完整动作序列及任务状态；不必重复写场景加载和事件逻辑。试剂和样品的生化变化不在本模块中求解，后续以状态表示，不伪造实验成功。

## 固定数值验收

资料原文及图片始终进入生成和审查上下文，但**尚未将任意资料中的所有参数自动转换成可信验收值**。关键尺寸必须通过 `--checks`（固定验收文件）绑定；未绑定的要求明确保留验证缺口。该文件不属于模型可编辑工作区。

文件包含 `jobs`（按生成任务编号提供单资产检查）、`fits`（配合检查）、`targets`（操作姿态）、`payload_mass_kg`（搬运物质量）。计划生成时模型看到这些约束，必须保留对应任务编号。

下面仅为格式示例，数值和名称均为开发者合成，不代表真实仪器：

```json
{
  "jobs": {
    "instrument": {
      "dimensions": [{"id":"width","geoms":["base_geom"],"axis":0,"expected_m":0.1,"tolerance_m":0.0001}],
      "required_interfaces": ["press"],
      "joints": []
    }
  },
  "fits": [{
    "id":"tube_socket", "outer":["rack__left_wall","rack__right_wall"],
    "inner":["tube__left_surface","tube__right_surface"], "axis":0,
    "clearance_m":[0.0002,0.0008], "evidence":"资料包中的明确配合要求"
  }],
  "targets": [{
    "id":"press", "site":"station__press", "tool_site":"gripper__tcp",
    "offset":[0,0,0.03], "quaternion":[1,0,0,0],
    "position_tolerance_m":0.002, "angle_tolerance_rad":0.05,
    "allowed_contacts":[]
  }],
  "payload_mass_kg":0.1
}
```

单资产尺寸采用实际几何包络；配合尺寸采用指定坐标标记间距，并核对标记是否位于所属部件实际碰撞表面（0.5毫米内）。仍需来源/视觉确认标记对应的是目标孔壁，不能把任意两点的间距称为通用孔径验证。

操作目标的位置偏移与四元数相对目标接口，四元数顺序为标量在前。允许接触只能由固定验收显式列出精确几何名称对；模型不能自行添加豁免。

## 交付与规划反馈

`runs/<运行名>/result.json`（结果报告）给出状态、预算、最新场景相对路径、完整场景摘要与未验证项。`planning_handoff.json`（规划交接文件）给出同一摘要、计划和验收条件。`stages`（阶段版本目录）保留全部脚本、局部补丁结果、产物、渲染和检查报告。

主要状态为 `candidate_ready`（工程候选就绪）、`needs_review`（需要复核）、`needs_environment`（环境未就绪）、`asset_repair_budget_exhausted`（资产修复预算耗尽）、`scene_repair_budget_exhausted`（场景修复预算耗尽）及 `paused`（暂停）。只有工程检查和视觉审查都通过，才返回候选就绪；它不等于完整实验成功。

### 只读补证与量测异常

审查不确定时，检查规划器可请求剖视或关节静态姿态，以及场景专用的几何对距离、实际承托、周边净空区、法兰安装检查。工具读取已编译产物，不执行建模脚本、不改交付几何、不推进动力学。`pairs`（指定几何对）保留距离、最近点和法向；`support`（承托）支持限定同一实例及其声明支撑对象内的几何；`perimeter`（周边区）检查外包络周围指定宽度、高度范围内的矩形带，区分底部支撑与周边侵入；`mount`（安装）报告工具相对固定法兰的实际变换和近邻机器人几何，不能证明未建模电缆的净空。新装配记录工具原始根变换，旧产物没有该记录时明确标注不可比较。

距离不能只相信一个数值。框架核对最近点间距、实际碰撞形状表面和支撑平面；主引擎结果异常时，尝试有分离平面证书的解析距离、箱体分离轴穿透核验及经过同样检查的备用算法。两个引擎结果均不可靠时，用独立 GJK（凸体距离算法）的上下界收敛与表面见证点再次复核；它不猜测穿透深度。仍无法核验时报告量测错误，不伪装成几何通过。网格按引擎凸包参与查询，通过支撑面多边形核验最近点，不能误用视觉凹网格表面代替凸包。承托搜索范围仍由支撑公差控制，但正间隙超过10微米不计作实际接触；此阈值是数值容差，不是稳定性或制造精度认证。

`--max-evidence-rounds`（每次审查最多补证轮数，默认6）与 `--max-evidence-plan-attempts`（每轮检查方案尝试数，默认5）可调整且不改变运行身份，调用仍受总预算约束。空方案、无效名称和重复成功请求会返回具体反馈，有界重新规划，不因第一次空方案直接结束。失败检查可重试；未完成的检查不能被后来无关的成功图片抵消。每次检查和停止原因保存在阶段目录与最终结果的 `evidence_outcomes`（补证结果）中。

新增停止状态：`evidence_planning_exhausted`（检查方案尝试耗尽）、`evidence_rounds_exhausted`（补证轮数耗尽）、`needs_check_support`（检查能力不足或量测异常）。它们与资产几何修复失败分开；增加几何修复轮数不能修好检查工具。确认缺陷后仍由既有受限修复流程处理。

跨本次源码升级须使用 `scripts/prepare_scene_continuation.py`（离线续接准备工具）的 `--kind evidence_checks`（检查升级模式），提供匹配旧运行身份的源码摘要清单和新的运行名。工具验证旧证据、复制账本和原模型，要求没有未归档阶段或结果不明调用；不调用模型、不覆盖旧运行，不把旧结论自动改成通过。下一次正式续跑会在新框架下重新装配和检查。

### 分阶段审查与恢复

单资产审查检查本体缺陷，收到原始参考图片、依赖的实际渲染和几何接口信息。本体穿模、缺件或明确要求冲突仍须修复。需要装管、组合装配后才能检查的事项可返回 `defer`（延后验证），记录到 `deferred_checks`（待验证清单），资产状态为 `assembly_ready`（可装配但尚有待验证项）；依赖装置可继续生成。这不是跳过验收或宣称资产已全面通过。

原始资料和只读数值契约决定固定要求；规划模型提出的暂定布局数值不自动成为硬规格。资料允许自由设计的尺寸可以依据依赖几何调整并记录依据，不需要人工批准模型自己的暂定值变更。生成和审查上下文都显式提供 `fixed_contract`（固定验收契约）。

`repair_directive`（修复决策）随数值反馈同时传给建模器和审查器，并保存于检查点；不能只将失败报告传回而丢掉“应该修什么”的决策。`instance_contract`（实例数量约定）列出框架将创建的实例；同一资产被重复实例化时，审查必须报告 `prototype_units`（单模型内的完整资产数量），要求为1。多支管不能先塞进一个模型，再由场景按数量重复复制。

运行目录中创建 `pause.request`（暂停请求文件）可在生成或审查阶段边界暂停，等待在途请求保存后再停止，不强杀请求；审查内部的格式重试最多完成三次后返回边界。恢复前移除该文件，再使用原参数续跑。

完整场景审查必须对每一项场景待验证事项给出证据及处理结果；遗漏或未解决不能通过。操作阶段事项继续保留在结果与规划交接文件中，静态模式不因未执行动力学而要求人工审批。精确尺寸若没有独立量测仍列为未验证，图片不能替代数值证明。场景布局或资产版本改变后，旧的待验证事项解决证据不继续生效。

`uncertain`（当前阶段证据不足）必须提供 `blocking`（具体阻断原因），汇总到结果中的 `blocking_reasons`（阻断原因列表）。恢复这样的单资产任务时先重审原模型，仅在审查发现实际缺陷后才进行几何修复。连续格式错误只重试审查，不触发盲目建模。

静态预览只检查当前几何布局。若工程与外观检查通过，而剩余事项需要规程初始状态配置、其他静态配合姿态或操作执行，场景审查可将其显式标记为 `out_of_scope`（超出当前预览范围），逐项说明依据及目标阶段。结果状态为 `static_preview_ready`（静态布局预览就绪），相关事项仍为 `pending`（未验证），保留原阶段、目标阶段和证据，不记为已解决。它不同于完整场景候选通过，不能作为完整规程起点或操作可执行的认证。当前缺件、数量错误、可见穿模和悬空仍阻断；完整模式不接受这条例外。场景审查现在同时接收全景和每类实例在实际场景中的近景，不改变姿态或推进仿真。

2026年10月13日阶段审查升级提供限定的离线复制工具 `scripts/prepare_scene_continuation.py`（场景续跑准备脚本）。它核对旧实现清单、归档和调用摘要，拒绝未知请求、未归档工作区及其他源码变化，保留原运行和累计预算。新运行将可复用模型标为 `review_pending`（等待新规则重审），不把旧的不确定结论改成通过；该工具只处理本次已知审查修改且尚未装配的运行，不能用于绕过任意代码或验收变化。
