# 当前生成与恢复链路的契约审计

2026-10-17 工程记录。本轮对 NP-001 静态场景链路进行了代码审查、离线行为测试和原归档收据回放，没有调用正式模型，没有修改历史资产、账本或实验结论。

## 根因与改动

上次失败的直接原因是：完整静态检查合法返回 `skipped`（当前模式排除），恢复消费者却不接受该状态。更深的问题是多个模块各自定义报告状态、完成条件和异常归属；旧测试大量使用简化合成报告，没有证明真实生产端的报告能够经过恢复消费者。这是工程实现和验证缺口，不能归因于资产生成模型。

新增 `src/asset_generation/check_report.py`（检查报告契约），供生产端、执行后端、主流程和恢复消费者共同使用。它统一状态、条目身份、覆盖缺口、完成条件、总状态和检查错误报告，没有改变几何验收阈值。恢复请求和结果的范围、版本及故障结构由 `scene_generation/capabilities.py`（恢复能力模块）集中校验。

修复的具体风险：

- 静态排除只接受固定配置允许的检查编号；不能替代必要检查、覆盖已执行缺陷或充当局部通过证据。只有排除项的报告不能通过。
- 空报告、重复编号、总状态矛盾、带缺口或碰撞的通过，以及错误类型的嵌套字段均被拒绝。未量测和错误数量不能因为详细诊断列表截断而消失。
- 检查程序错误形成工具故障；生成的模型描述格式错误仍进入资产反馈。工作进程、后端和主流程共用错误信封，保留异常类型、来源和原诊断。公共抛错助手不再冒充实际故障模块。
- 渲染报告、输出目录和真实图像交付不一致时，保留已有数值检查事实并报告工具错误，不让作者修改几何去迎合证据交付错误。场景归档保存最终报告，避免磁盘与内存结论分歧。
- 非法能力提案形成持久化故障，恢复不重复崩溃，其他能力仍有查询机会。局部结果不能越出请求范围，不能清除无关缺口、未展开的诊断计数或其他几何对的错误。
- 补证结果逐项对应原请求；缺失、重复或无关的结果不能由总通过状态代替。初始几何清单也经过校验。补证阻塞声明中的错误类型字段不再触发未捕获异常。
- 计划、验收配置、环境、修复范围及清单引用先校验类型，再做集合运算或引擎查询。部件按名称引用，不能把整数或布尔值当作引擎索引。重复尺寸和关节检查在输入端拒绝。

## 审计边界清单

| 边界 | 已核对的约定 | 主要验证 |
| --- | --- | --- |
| 已提供资料包 → 任务与场景计划 | 资产、实例、依赖、布局、固定环境；评测不接提取和搜索 | 输入及场景主流程测试、嵌套结构变异 |
| 生成响应 → 构建输入 | 首次响应、修复唯一文本替换、脚本上限、来源 | 原生成测试及本轮变异 |
| 交互清单 → 引擎引用 | 字段类型、名称、接口及约束引用 | 真实编译合成资产及变异 |
| 检查生产端 → 后端 → 主流程 | 状态、身份、模式排除、错误归因、图像交付 | 真实本地工作进程、错误注入、归档回放 |
| 主检查 → 能力提案 → 执行结果 | 同一问题、版本、范围、故障结构、执行记录 | 调度与故障测试、提案故障恢复 |
| 局部结果 → 合并与决策 | 只覆盖实际检查；保留缺陷与无关缺口；共享错误不能互证 | 局部合并、持续未知、共享组件错误测试 |
| 审查 → 补证 → 再审查 | 实际清单、请求关联、逐项未解决记录、接受和修复分流 | 补证循环测试、计划与结果变异 |
| 已确认缺陷 → 定位 → 修复范围 | 未知不授权修改；定位确认缺陷；依赖只扩大复核范围 | 既有恢复主流程测试，本轮完整回归 |
| 修复提案 → 执行 → 效果登记 | 语义参数、输入和问题身份、执行后才判无效 | 原因文字变化、不同摆放、执行后去重测试 |
| 中断/预算 → 恢复 | 收据先保存、动作保留、账本不清零、旧证据失效 | 中断、恢复、预算与失效证据测试 |
| 归档/升级 → 新运行 | 源码身份、归档和调用摘要、受限迁移清单 | 既有迁移测试、真实摘要核验；本轮未迁移 |

清单覆盖当前生成与静态恢复的接口边界，不是对所有输入组合的穷举证明。未启用的资产提取和联网搜索保留原实现，随完整测试回归，本轮未重新认证其外部服务契约。

## 两轮审查与测试

第一轮审查关注提示、校验及异常路径：追踪真实报告从检查器到决策的传递，纠正合法静态状态被拒绝、空报告假通过、程序错误混入几何修复、嵌套字段先运算后校验和部件索引误接受。真实收据回归保留生产端实际字段，没有把合成样例简化成只满足消费者的结构。

第二轮审查关注证据、预算及恢复：复核版本身份、局部合并、共享故障依赖、收据回放、图像与归档一致性、动作计数及旧运行升级。额外修复只有错误列表而无摘要计数时的局部合并漏洞，以及能力提案异常无法持久化的问题。没有扩大模型编辑范围、提高预算或更改验收公差。

最终完整回归：470 项测试通过，86.686 秒。日志为 `.cache/contract_audit_20261016/full-delivery.log`（最终完整测试日志）。其中 `tests/test_contract_boundaries.py`（契约边界测试）包含 22 项测试，嵌套结构变异覆盖超过 1,000 个变体。针对性结果保存在同目录的 `boundaries-complete.log`（契约测试日志）。

中间完整测试曾发现新增测试模块引用错误，以及统一错误报告时遗漏原超时诊断文字；两者修正后再跑完整回归。测试通过不等于所有输入均已覆盖，也不等于正式实验通过。

## 真实归档验证

原运行：`runs/np001_recovery_20261016_1745`。新增 `scripts/audit_scene_contracts.py`（只读契约审计脚本）核对归档和已完成调用的文件摘要，读取原检查报告及动作收据，使用当前消费者回放决策。它不执行建模脚本、不重新量测、不调用模型；输出必须写到原运行以外的新目录。

最终输出：`.cache/contract_audit_20261016/np001_archive_final/audit.json`（审计结果）。16 份报告、15 份恢复收据全部通过契约校验；回放决策为 `repair`（定向修复），原运行前后摘要一致。原先被拒绝的第一份静态补查收据可以正确合并，保留 5 对确认碰撞、3 对碰撞量测缺口和 3 项静态模式排除。

这证明此次真实证据能被当前消费者正确消费，并恢复到应有的修复决策。它不证明缺陷已修好、缺口已消除或正式闭环成功。原实验的 `needs_environment`（需要检查环境支持）结论没有改写。

`tests/data/np001_static_recheck_contract.json`（真实收据的契约字段摘录）保存原路径和摘要，属于历史模型运行的回归资料。其余新增场景与模型响应是开发者合成数据，没有混作新模型实验。

本轮变更超出已有 `main_check_recovery`（主检查恢复迁移类型）的允许文件范围。没有放宽迁移白名单，没有改旧身份或创建续跑副本；旧实验不能直接用新源码原地续跑。后续若要复用旧资产，需要单独实现并验证相应迁移，不能仅把新增文件加到白名单。

未验证本轮改动后的正式模型端到端运行、真实容器后端、新复杂几何及任意断电组合。静态检查不认证轨迹、动力学操作或湿实验完成。未来新增能力必须附生产端到消费端的行为测试、局部覆盖和异常测试；增加状态或注册项不构成完成依据。有限测试与审计不能保证今后绝无契约缺陷。
