# 同服务商模型切换续跑

`scripts/prepare_model_continuation.py` 是离线工具，不发送请求。它仅支持已中断或服务暂停的批次、已暂停运行和排队项目；拒绝已结束项目、未经明确处理的未知请求、代码/配置漂移、损坏归档和重复目标目录。

它复制运行到新名称，保留调用账本、资产、检查点、数值阈值及累计预算，仅修改目标模型和对应运行绑定。原身份记录于 model_history 和 model_transition.json；原批次不改写。新增请求仍由现有框架逐次记录请求及响应模型。混合来源不能当作单模型实验。

当前准备的批次：static5_sol_20261018。NP-001 继承 static5_20261018_152958_np001 的 36 次请求记录（26 成功、10 失败）、8 个资产及 stages/00016_scene 检查点。后续模型 GPT-6.1-sol，服务地址 https://api.gpugeek.com/v1，继续使用项目既有凭据；未读取或复制密钥。随后按 NP-043、NP-088、NP-052、NP-002 顺序执行。

用户启动：

```powershell
Set-Location 'D:\harness\new_harness'
& 'C:\Users\31408\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe' -NoProfile -File '.\scripts\run-scene-batch.ps1' --batch static5_sol_20261018 --resume --execute
```

每案例总预算仍为 400 次请求、120000000 预留令牌；不是额外授予这些预算。NP-001 已使用的 36 次请求继续累计。预留令牌不是价格或实际账单。

工程审查一：模型名称来自用户截图；新请求参数沿用同服务商兼容接口。迁移不修改提示、验收标准及生成资产；不会回写旧调用模型。未知请求拒绝迁移，复制失败不会发布可执行批次清单。

工程审查二：采用原恢复函数只读验证检查点，逐文件对比复制结果并再次校验源文件；原身份、预算和账本保留，目标绑定按同一实现重建。不删除历史实验。发现并修正了迁移检查点校验与正式恢复契约重复的问题；对应测试预期改为实际 StaleEvidence（过期证据）异常。

验证：7 项迁移风险测试及 14 项批次回归测试通过；真实输入按照正式入口重建的完整身份与迁移后身份一致；实际批次不带 --execute 的准备入口通过，新增模型请求为 0。

未验证：服务商对 GPT-6.1-sol 的图片、上下文容量及输出参数支持、在线可用性、视觉审查结果。截图没有提供这些限制，不能以离线配置通过代替在线能力验证。切换模型会重启当前视觉审查的模型判断，但复用已有资产和场景检查点。

## 2026-10-19：保留未知请求后切换模型

用户明确决定换模型续接时，可在离线迁移命令加 `--preserve-unknown`。默认仍拒绝未知请求。该选项仅在新副本中将旧模型的 `pending` 标记为 `unknown_not_replayed`，同时保留 `outcome_unknown=true`、原模型、调用索引和全部预算；不宣称旧请求失败、免费或取消，不自动重发旧请求。来源批次及账本逐文件校验且不改写，目标副本记录迁移前身份和未知调用编号。新调用使用新模型，此运行属于混合模型来源。

若已有落盘响应，必须先恢复响应；若预留尚未发送或缺少原模型身份，该选项也不会绕过校验。此选项不能保证服务商可用，也不会缩减过大的审查上下文。
