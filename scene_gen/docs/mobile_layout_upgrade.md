# 移动机械臂与多工作台升级

本次在原有场景协调、资产生成、装配、检查和修复流程内升级，没有另建一套代理系统。正式模型仍由用户选择并运行，工程测试使用明确标注的开发者样例。

## 已实现的范围

模型先提出以原点为中心的房间大小、工作台数量及各台尺寸、位置、朝向，然后直接继续执行，无需逐次人工批准。可以保留独立落地仪器，同一台移动机器人可为不同仪器提出不同停靠位置。

基础资产形成可加载候选后、夹具和末端生成前，使用其实际几何摘要进行一次布局细化。最多三次格式修正，共享总调用账本；未得到合法细化时继续保留原布局，不阻止其他资产生成。之后仍由原有场景审查与定向修复继续调整。

修复可以改变工作台数量、尺寸、位置和朝向，改变初始停靠位置，重新安排仪器。新增工作台须写明理由。房间在首份计划确定后保持不变，仪器不能缩放，机器人规格和固定验收不能由修复模型修改。理由的合理性还需要场景审查，不声称文字校验就能保证设计正确。

移动桌子时未显式重定位的桌上实例会跟随；支撑链随父对象一起移动，不缩放资产。删除桌子必须安置其所有实例。跨桌调整要同步支撑关系。布局变化进入证据身份，依赖装置重新复核；不重置资产尝试或调用预算。

工作台与实例均按世界坐标装配；切槽中心和桌边夹持方向使用所属桌子的局部坐标。承托检查只认可指定桌面，不能由另一张相邻桌子“代替通过”。移动底盘取消旧的桌面中央机械臂保护区，仍保留桌边、桌腿、孔槽底厚和面积限制。

## 机器人来源与近似

当前默认是 **PAL Robotics TIAGo OMNI（帕尔机器人公司单臂全向移动整机）**，替换前一版合成移动底盘与 FR3（弗兰卡科研机械臂）的组合。厂家描述中的原底盘、升降躯干、头部与七关节手臂直接作为整机装配，不额外生成底座或立柱。

厂家的0.35米升降关节已保留；布局坐标仍使用平面移动与偏航近似，不声称已完成麦克纳姆轮地动力学。生产配置提供裸腕法兰供原有末端任务装配；展示配置另带原厂平行夹爪。来源、固定版本、参数、两轮审查及查看命令见 [整机接入说明](tiago_omni.md)。

## 检查的含义

- 保留原来的碰撞、规格、逐组件承托和配合检查；补充房间边界及工作台占地检查。未知、失败、部分场景和质量通过继续区分。
- 用底盘外接圆、保守障碍包围盒与有限分辨率网格评估可连通区域；不允许网格对角穿越障碍。工作台下方不作为可通行区。此方法可能偏保守，不能证明不存在其他路线。
- 对各实例现有接口标记，或无接口时的几何中心，给出肩部到目标的距离建议及候选停靠点；也核对模型提出的停靠点。**没有求解逆运动学、机械臂绕障、自碰撞和操作朝向，不能将建议写成任务可执行的证明。**
- 对已建模的非机器人移动/转动关节，抽查改变关节坐标后是否产生运动学变化。未认证驱动、闭链约束、开合空间及完整运动；需要活动却没有建模的机构仍由资料和视觉审查发现。
- 粗略操作性建议本身不作为整轮停止门槛，进入审查与说明。已确认的物理缺陷继续修复，不能以“生成优先”为由改成通过。

默认是静态场景阶段，不生成轨迹，也不执行完整规程。

## 持续交付

每个已创建的运行都会尽早写 `scene_document.md`（场景交付说明）。规划请求失败时仍有失败说明；规划成功后先发布房间、工作台与机器人，基础资产逐个可用后更新部分场景，再检查及修复。

`scene_status.html`（状态页面）、`preview.json`（轻量预览索引）、`result.json`（完整结果）、`planning_handoff.json`（后续规划交接）共用已发布模型身份。交接文件使用已发布模型对应的布局，不混入尚未成功装配的修复计划。说明明确列出已装配实例、缺件、版本差异、来源、近似、预算及证据缺口。

无法编译的资产、局部细化失败或审查尚未完成，不取消已有候选。预算用尽、用户暂停、源码/证据被改变或请求结果不明仍保留边界与记录。没有有效模型时只能交付说明及失败证据，不伪造成功场景。

## 默认预算与兼容

单规程累计上限：**800 次模型调用、240,000,000 预留词元、80 轮场景迭代，每资产累计 60 次候选尝试**。新单次运行和新批次采用这些默认值。上下文窗口和单次输出额度没有随总预算翻倍。资料读取、布局细化、资产生成、审查及修复共享账本，恢复不清零。

旧批次和原模型产物没有改写。源码及环境身份已经变化，新实验使用新名称，不能把旧运行强行当作同版本恢复。需要旧版固定桌面时显式选择 `config/scene_environment_fixed.json`（固定环境配置）。库中小规模开发测试默认值与正式入口配置分开，测试不会隐式开大预算。

## 用户实验命令

工作目录是 `D:\harness\new_harness`。先读取本次全量工程测试生成的验证收据；若以后改了源码，重新执行 `.\test.ps1`（本地测试脚本）。

```powershell
Set-Location D:\harness\new_harness
$verified = Get-Content .cache\verification.json -Raw | ConvertFrom-Json
if ($verified.status -ne 'passed') { throw '工程验证尚未通过' }
$verifiedImplementation = $verified.implementation
$sceneRun = 'mobile_np001_' + (Get-Date -Format 'MMdd_HHmmss')
.\run.ps1 scene --backend local --static-only --protocol-pdf D:\harness\selected50_protocols\NP-001\source.pdf --package D:\harness\selected50_protocols\NP-001\asset_package.md --run $sceneRun --execute --expected-implementation $verifiedImplementation
```

`--backend local`（本地后端）使用既有本机执行器；它不具备宿主文件和网络的系统级隔离。没有新开放任意工具或改变原执行权限。

该命令使用当前服务配置中的 GPT-6-astra（模型标识），请求及响应模型分别记录。助手本轮只做离线工程验证，没有执行此命令。NP-002 可将两处规程路径和运行名称中的编号同时改为 NP-002。

```powershell
Get-Content "runs\$sceneRun\scene_document.md" -Encoding utf8
.\run.ps1 preview --run $sceneRun
```

不保证一轮模型实验就收敛。实际模型能否设计合理布局、资料中的活动结构是否完整，以及这次升级相对旧批次的质量改善，需由新正式实验验证。

两轮工程审查、已修复的回归问题、离线重装配结果及未验证范围见[工程审查记录](mobile_layout_review.md)。
