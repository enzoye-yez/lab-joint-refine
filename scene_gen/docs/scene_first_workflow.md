# 先装配、后验收的静态流程

后续更新：本记录中的局部停止与恢复规则已由[持续推进优化](continuation_policy.md)调整；本页验证数字是当时版本的历史记录。

2026-10-19 工程更新。只适用于 static（静态）流程；full（完整操作检查）路径继续使用原流程。未启动新的正式模型实验。

## 产物与验收分开

1. 模型按计划生成资产候选。准入只核对实际可加载性、清单引用、构型选择及工具安装所需接口。质量尚未检查，明确保留待检查记录。
2. 资产生成按依赖顺序轮转；每轮每个符合条件的任务一次生成机会。单资产格式修复不占用其他独立任务的首次生成机会。全局请求与令牌预算仍是硬上限，服务重试也继续记账；不能保证任何给定预算都足以生成全部资产。
3. 准入与图片生成分进程执行。渲染失败保留已验证的加载证明，依赖设计收到实际可得的接口、图像及未验收状态。
4. 可加载资产立即组成诊断场景，编译结果先归档，再进行数值检查、只读补查、单资产视觉审查和场景视觉审查。审查者收到实际装配图片。
5. 单资产数值结果、视觉缺陷和场景结果共同进入决策。每条继承的资产检查绑定任务及其实例；局部未知不能被场景通过结论覆盖。已确认缺陷进入原定向修复流程，纯未知不成为几何修改理由。
6. 每次更新保留上一版可加载产物。替换失败保存失败尝试及旧候选；不能以旧候选伪造修复成功。源码改变但几何未改变的已执行修复也要评估无效性。

## 查看与状态

`result.json`（结果文件）的 `scene_artifact`（场景产物路径）不再要求质量通过才提供。`assembly`（装配信息）分别记录是否存在、是否缺件、质量是否通过、当前问题和生成尝试。

运行目录的 `scene_status.html`（诊断状态页面）显示模型链接、当前图像、缺失任务及非通过检查。`run.ps1 preview --run 运行名` 可以打开未验收场景；查看时不推进物理时间。批量报告为诊断场景导出预览，仍以非成功状态记录未通过的实验。

资源缺失或结构损坏的资产不能强行装入。独立资产仍可生成并形成明确标记缺件的部分场景；不会生成占位资产冒充正式模型输出。缺少承托对象的部分场景可能显示悬空，该缺件场景不能验收通过。

## 证据与恢复

场景在质量调用前单独归档。检查中断、模型请求中断、预算耗尽不会删除已发布版本。首次生成阶段请求预算或服务故障发生后，只用已经存在的资产保存诊断场景，不再追加付费请求，然后保留原中断原因。

已完成量测按场景内容、计划、实现版本绑定；恢复复用收据。单资产审查绑定实际产物、布局、依赖几何及实现版本。源码升级不能复用旧通过结论。归档摘要不匹配直接拒绝复用。

磁盘不可写、编译器无法加载所有必要组件、用户在首次装配前主动停止等情形仍可能没有完整场景。质量检查和补查能力没有因此扩展，保留场景不代表已经解决全部悬空或穿透。

## 两轮工程审查

第一轮：提示、准入和异常路径。发现依赖提示仍声称原图已经审查、渲染与准入耦合、旧状态短路后续任务；已改为真实阶段说明、独立渲染和逐任务调度。原验收公差与固定检查器不交给模型修改。

第二轮：证据、预算和恢复。发现审查记录继承归档目录会错绑版本、恢复可能重复量测、相同几何修复未被评估、服务中断可能丢失本轮可查看结果；已加入独立场景发布、内容绑定收据、实际执行结果评估和中断前本地发布。所有修复仍需行为测试和真实归档装配验证，不声称绝对无漏洞。

验证日志和只读归档回放保存在 `.cache/scene_first_20261019/`。真实归档重装配属于工程回放，不计入新模型实验成功率。

补充显示边界：离线渲染容量按实际几何、站点、物体和肌腱数量分配，避免默认 10,000 个可视几何的截断。交互查看器当前安装版本容量为 100,000，仍受独立的模型规模限制。静态其他姿态尚待验证的预览不标为最终质量通过。
