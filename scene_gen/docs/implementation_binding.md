# 实现版本绑定、证据进展与恢复验证

2026-10-17。本轮在现有框架上增量修复，不执行正式模型实验，不修改生成资产或旧运行结论。

## 实际执行的版本

`src/runtime_bootstrap.py`（源码启动层）在导入工程包前读取三个工程包的递归 Python（编程语言）源码及启动层本身，计算清单摘要。工程模块从这份内存源码编译加载，包括稍后才导入的模块；不读取工程字节码缓存，也不从磁盘补入快照之外的新工程模块。工作进程使用同一启动层和主进程传入的指定摘要。容器的源码根目录 `/app` 与本地的 `src`（源码目录）采用同一相对路径清单。

正式场景入口要求 `--expected-implementation`（指定已验证实现摘要），并同时检查实际加载的固定源码。直接调用正式 `SceneRun`（场景调度器）也受此约束。离线开发替身必须明确标记来源，不能算作正式生成。

模型请求每次尝试前、工作进程执行前后和阶段提交前检查源码及依赖版本是否改变。漂移抛出 `ImplementationDrift`（实现版本变化），继承证据失效异常，直接暂停；不转换成资产构建失败或交给模型修复。请求途中漂移时先归档已收到的响应，再拒绝消费，保留计费记录；恢复原版本后可以复用响应。

`implementation_sources/<摘要>.json`（执行源码归档）保存清单和对应源码内容；离线回放还保存实际执行脚本的源码和摘要。输入、配置、依赖版本及其覆盖说明继续单独记录。依赖只记录版本号，没有封存第三方二进制或操作系统环境；本地工作进程也不提供文件和网络权限隔离。

## 验证与正式入口

```powershell
Set-Location D:\harness\new_harness
.\test.ps1
$verified = Get-Content .cache\verification.json -Raw | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or $verified.status -ne 'passed') { throw '工程验证未完成或未通过' }
$verifiedImplementation = $verified.implementation
```

验证收据绑定本次执行的源码清单、依赖版本和测试命令。收据处于 `running`（运行中）或 `failed`（失败）时不能当作通过；硬中断可能留下运行中记录。后续正式场景命令须增加 `--expected-implementation $verifiedImplementation`，源码变更后需要重新验证。本文仅说明接口，不表示用户已授权立即运行正式实验。

队列执行器沿用准备阶段冻结的源码身份，实际子进程通过固定源码启动层运行。没有自动启动任何队列，NP-002 仍保持暂停。

## 迁移与旧证据

同版本恢复仍使用原运行名和 `--resume`（接续）。升级实现时使用 `scripts/prepare_scene_continuation.py`（离线续跑副本工具）的 `--kind implementation_binding`（实现绑定升级类型），必须提供与旧身份相符的 `--before-sources`（旧源码清单）。不允许手改旧运行身份。

此升级类型仅处理尚未通过验收、没有未归档工作区、没有待核对未知请求的静态运行；其余情况明确拒绝。迁移保留原资产、账本、预算、阶段和历史动作，同时更新顶层身份与完整绑定记录。旧补查记录转存历史，不充当新实现的通过证据。

对于历史上只存了实现摘要、没有旧源码清单的运行，可以显式选择 `--kind archive_revalidation`（归档重验续接），不传旧源码清单。它仅接受全部资产已完整归档且没有待处理未知请求的未通过静态运行，核验调用和阶段摘要后保留资产、账本及预算，强制重新量测和审查全部资产、重建并检查场景。收据明确记录 `legacy_source_verified=false`（旧源码未完整核验），不宣称做过源码差异核对，不把续接结果算成原冻结实验成功。普通源码升级缺少清单时仍拒绝，不会自动采用此路径。

迁移后的资产先对已归档几何执行只读复查，再进行视觉复审，不执行原建模脚本。量测或程序错误继续保留复查义务；仅有确认缺陷时才进入模型修复。之后重新装配并检查完整场景，旧数值和视觉通过结论不自动继承。不同实现的模型请求缓存、补查输入身份分别绑定实现摘要。

## 实际证据进展

`src/scene_generation/progress.py`（证据增量模块）比较动作前后、实际覆盖范围内的证据：

- 检查整体完成，以及具体未知几何对被可靠量测；局部解决一个几何对也算进展。
- 新增的确认缺陷；几何对使用身份集合比较，支持非碰撞检查确认缺陷。
- 新增的几何名称到实例映射；已有定位不会重复计功。
- 由合格证据解除的故障，及仍未解除的检查与几何对范围。

动作失败时不记进展；缺失结果行不冒领覆盖。调度器的 `effective`（动作有效标记）采用上述事实，不再按报告摘要变化计算。完成状态、去重和预算继续独立管理；一个动作无进展不妨碍另一种适用能力执行。未知不会被转换成缺陷或通过结论。
