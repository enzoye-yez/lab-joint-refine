# 架构与资料接口

## 流程边界

本模块只完成“规程与资料 → 资产需求和参考资料包”。正式来源始终记录请求服务商、基础地址、请求模型、响应模型；第三方返回的模型标识不等于对其上游身份的独立认证。

1. `documents.py`（文档模块）默认只读取 PDF（便携式文档格式）。XML（可扩展标记语言）只有明确的补证原因及检索词时才解析并选取相关块；保留原因、原文摘要、页/节点标识及解析版本，禁止实体展开与外部资源读取。
2. `blocks.py`（结构块模块）、`workflow.py`（任务状态模块）和 `resolution.py`（身份与字段解析模块）执行局部提取、分页匹配和登记表提交；`prompts.py`（提示模块）与 `providers.py`（服务模块）执行模型请求；`search.py`（检索模块）选择模型原生搜索或可选 Tavily（检索服务）。原生搜索使用同一模型密钥。
3. `contracts.py`（固定约定模块）检查格式、引用、数量、对象关系、冲突来源及参考规格差异；模型只能修改自己的候选输出。
4. `pipeline.py`（流程模块）维护阶段输出；`storage.py`（存储模块）负责预算、缓存、摘要和恢复。
5. `network.py`（网络模块）只提供有界数据请求；没有命令执行、动态代码导入或脚本执行工具。
6. `pages.py`（网页模块）无凭据读取搜索引用的静态网页，提取正文和图片引用；`images.py`（图片模块）下载选定的栅格图片。
7. `preflight.py`（输入预检模块）检查单组或文件集合的解析、提取请求大小和已知预算下限，不使用凭据与网络服务。

## 真实输入与长文档

输入可以是带论文元数据、正文、表格、图注、参考文献的期刊文章。默认只有 PDF 全文进入来源档案；未用 XML 不读取、不校验、不计算摘要，也不参与缓存身份。明确缺口后，XML 按检索词匹配正文块或章节，只追加选中的非重复块；空白标准化仅用于重复比较，不修改原文，且保留单位大小写、数字间隔和上下标。查询不命中或过宽时明确报错，不默认整篇处理。补证原因及选中来源进入身份。XML 表格和上下标解析仍保留，PDF 事实优先；不能声称关键词筛选已经解决语义对齐或信息完整性。模型自主触发补证尚未接入。

文档总长度上限与单请求上限分开控制。提取规划使用和正式模型请求相同的消息构造函数，根据编码后字节数细分；分段保留来源标识和字符偏移，不丢弃后续文本。每一段都接受原文引用校验。

提取仍限定每页最多 8 项候选、16,000 输出字符、请求 6,000 输出令牌。正文按带偏移的原文行组成结构单元，初始目标 4,000 字符；短行并入邻接单元，超长行采用平衡分割，保留全部字符。这里使用文本行和换行结构，不声称已实现完整的表格或章节语义解析。每个来源附加最多前后各 160 字符的阅读上下文；模型只应提取标定范围内的事实。

局部提取请求完全不含历史资产库。模型返回 `inventory`（局部候选清单）和 `consumed_units`（完整处理的连续前缀单元数）。高密度内容先交付可完整处理的前缀，余下单元继续排队；首个单元无法完整处理或响应截断时，才细分任务。最小单元仍无法容纳则明确停止，不无限拆分、不删除短文本。`evidence_repair.py`（引用修复模块）继续只修引用，不能修改资产字段。引用存在和连续区间覆盖不证明语义完整。

身份判断与字段取舍是不同操作。身份页只包含标识、名称、类别、别名及规格名称/值/单位，不带所有对象的数量依据和引文。每页最多 12 项，并按序列化后的请求字节数进一步缩小；带上之前页的暂定对象，完整扫描所有已登记资产后才允许新增。类别只是判断线索，跨类别匹配可以复用原标识，并记录分类分歧。分页是模型逐页比较，不是独立的语义去重证明，也不保证等价于一次全局比较。

选定对象后，数量及字段按来源优先级和精确值在本地处理；相同值合并证据，数量不累加。同名字段直接对齐；不同名称的字段通过独立分页判断是否为同一属性；同优先级的冲突仅发送双方字段，由模型选择原值之一并记录理由。其他对象不进入字段比较。`incremental.py`（增量应用模块）保留未改变内容，应用决定并重映射步骤、关系和冲突；当前候选事务全部通过后才提交总表。

新操作的初始消息分别限定在 24,000 字节以内，并预留修复空间；格式修复仍受配置的总输入上限约束。单项描述或字段对自身过大时明确停止，不截断规格。资产总数只增加分页数量，不能保证任意巨大的单项对象均能自动处理。默认资产数量上限仍为 64；10/100/1,000 项合成测试验证分页机制，不能解释成默认配置允许 1,000 项。

`state.json`（持久化账本）保存版本化任务队列、原文区间、局部候选、分页游标、暂定身份、字段决定、待提交结果和修订号。`asset_workflow_v2`（第二版工作流契约）恢复直接从这些状态继续；已保存响应可补足“响应完成、任务状态尚未更新”的中断窗口。不再从第一段重演全部控制流程。代码实现摘要改变而契约及输入/语义配置相同时，记录实现变更后恢复；改变状态语义或操作协议必须升级契约版本并提供迁移，不能继续沿用同一版本标识。

`asset_package.json`（资产资料包）仍是唯一对外结果；候选和事务内部工作副本不作为另一份最终清单。发布前保存目标文件摘要意图，崩溃后只接受已登记的前后版本，再由持久化总表重新发布；无关篡改仍拒绝恢复。固定检查器保留名称/别名及规格的确定性重复检查，但不能证明语义同义、型号关系或单位等价。

`migration.py`（历史任务迁移模块）仅支持已经核对的历史源码版本。它在临时副本中消费全部已存响应，导入已确认总表、当前候选及已完成合并决定，再将未处理区间转换成新队列；迁移禁止网络，任何缓存未被消费、来源或响应不一致均拒绝。`extraction.py`（旧提取适配模块）和旧批次合并函数只用于该迁移及其回归测试，正常执行不再使用全局索引路线。具体操作见 [持久化任务恢复](merge_index_recovery.md)。

## 原生联网检索

使用 `/responses`（响应接口）及 `web_search`（网页搜索工具）。只有顶层完成状态、至少一个完成的搜索调用记录和结构化来源引用同时存在，才接受检索结果；回答正文中的普通链接不算来源。兼容接口可以只返回最小搜索记录和消息引用，不强制要求搜索记录包含动作与来源列表。

`references.search_records`（检索记录）保存响应模型、搜索标识、请求摘要和模型摘要；`summary_is_source_text`（摘要是否原文）固定为否。来源初始 `content`（正文）为空，状态为 `not_fetched`（未读取）。独立网页读取成功后才能作为规格引文来源；失败或超出每项资产页面数上限的引用不填充虚构正文。

网页快照经过已知密钥脱敏后缓存，以 `page_sha256`（页面内容摘要）和 `page_request_key`（页面请求标识）关联来源。支持页面元数据、图片标签、响应式图片和 JSON-LD（链接数据格式）的产品图片字段。不执行脚本、不跟随跳转，不支持动态页面渲染和 PDF 手册解析。每页读取、正文和候选图片数量均有上限；截断会显式标记。

## 资产清单

每项资产包含以下字段，机器字段使用英文以稳定接口：

| 字段 | 中文含义与规则 |
|---|---|
| `id/name/category/aliases` | 稳定标识、名称、类别、别名；类别仅仪器/容器/耗材/配件 |
| `quantity` | 正整数数量、明确/推断来源、依据、引文 |
| `requirements` | 目标规格与操作要求；每项含名称、值、单位、明确/推断、依据、引文 |
| `operations/evidence` | 参与操作、原文证据 |
| `parent_id` | 所属资产；必须存在且不得成环 |
| `queries` | 模型生成的检索词，执行次数受配置约束 |

全局清单另含 `steps`（步骤与资产对应）、`relations`（资产关系）、`conflicts`（文档冲突）、`assumptions`（假设）、`issues`（缺口）。每个冲突关联资产及具体要求，最终要求必须引用该冲突的 PDF 依据。检查只证明引用与格式一致，不保证模型已发现所有语义冲突。

## 产品参考与适配

每项资料包含不可由选型覆盖的 `target`（目标资产）、`references`（检索快照）、`selection`（产品选择）、`downloaded_images`（本地图片）与缺口说明。

选型模式：

- `reference`（直接参考）：选择了真实检索来源，没有声明改动。
- `reference_adapted`（改造参考）：列出对应目标要求、修改内容和理由；不能作为该商品的准确复刻来标注。
- `requirements_only`（仅按要求）：没有足够参考资料，按目标与显式推断继续生成。

产品规格必须引用选定来源中的原文。引用同名规格时，值或单位不同必须显式适配；当前不自动证明单位换算等价或几何适配可行。

图片记录区分页面链接、检索服务给出的来源关联和未核实关联；均不声称已经过视觉身份检查。同一图片被多个来源引用时保留 `source_ids`（来源标识列表），选型可引用其中任一已选来源。产品结构化图片优先于页面元数据、普通图片和响应式候选；这只是候选排序，不证明型号正确。下载失败不抹去引用，留作后续补全。

后续基准评测可人工提供相同的目标与参考资料结构；本版没有实现人工资料包导入命令，不能声称已有完整基准评测旁路。

## 证据与预算

模型/检索请求在发送前写入待完成记录并占用预算。响应保存后才标记完成。响应解析或格式修复也保留原始响应；错误正文和请求头不保存，已知凭据在模型返回内容中会脱敏。

原生搜索同时占用模型与检索次数，两项预算检查后才原子记入账本。网页读取与图片下载分别记账；预算暂停可以发生在同一资产的多个网页之间，恢复复用已成功的搜索、网页和模型响应。总预算允许增加，其余语义配置变化使旧证据失效。

`budget.py`（预算规划模块）在提取完成后按实际查询数和每资产一次选型输出后续预算计划。首次进入参考资料阶段预算不够则提前暂停；仅提取模式可先交付主清单。`limits.py`（输出上限核对模块）保存服务自报用量核对结果：报告超限暂停，缺失用量标记不可验证，不能据此证明费用硬上限。`probe.py`（接口探测模块）由用户显式执行，独立账本，最多4次小请求；不读取规程，也不自动修改正式模型参数。

单次搜索设置 `max_tool_calls`（服务端工具次数上限），返回记录超过上限即中止后续自动执行，保留响应及预算。新增参数在第三方兼容服务上的实际支持尚待用户验证。搜索预留包含额外上下文估算，返回后按每请求预留与报告用量的较大值累计，超出总量则保存后暂停；单次请求可能已经超支，缺失的用量也不能当成零费用。

网络中断、超时、服务端错误或无法解析的成功响应按结果不明处理，恢复时需要显式重试开关。明确拒绝的请求保留失败记录，下一次用户恢复可重新请求，预算不退回。

成功响应按请求内容摘要复用；同契约代码更新直接继续持久化任务，模型、语义配置、文档或契约改变必须显式迁移或新建运行。源目录以外的旧代码、旧配置、旧证据不参与此流程。

单次文件写入使用替换式原子写入，进程锁避免同一运行并发。多文件输出以发布意图恢复已知的中断窗口，检测到无法解释的不一致时拒绝恢复。摘要用于失效检测，不是防恶意篡改的密码学签名。
