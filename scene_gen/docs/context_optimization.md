# 上下文构造与恢复优化（2026-10-20）

当前行为以[架构修复记录](architecture_revision.md)为准：必要原文与大依赖资料支持准确分页，全部不同图片可分批送达；不是将它们全部固定在单条请求里。下文实现、数字及脚本命令为当时版本的历史记录，旧请求的精确构造回放需要当时绑定的实现。本次直接投影已归档请求的结果另见架构修复记录。

后续更新：本记录中的局部停止与恢复规则已由[持续推进优化](continuation_policy.md)调整；本页验证数字是当时版本的历史记录。

本次为工程修改与离线验证。对象是场景规划、资产作者、视觉审查、补证规划和场景修复使用的统一生成请求入口。没有发起正式服务请求，没有续跑实验，没有修改生成资产、验收阈值或原检查报告。资产提取与联网搜索模块不在本次改造范围。

## 实现

1. **统一入口。** `GenerationModel.ask`（生成模型调用入口）统一处理所有场景和资产生成请求。原审查适配器对真实模型交回原始上下文，避免先按通用字节折叠丢掉必须逐项回答的事项，再进行第二次压缩。

2. **当前状态与有界工作笔记。** 补查历史默认传递动作、结果状态、失败原因和完整原文引用，不累计重传完整报告及重复清单。修复格式纠错保留最新响应和错误；旧记录仍可读取。跨详情页允许模型提供有来源的工作笔记，最多 32 条、合计 8,192 字节，替换当前笔记而非追加对话。笔记明确标为模型归纳，不能修改检查报告、清除未知项或充当通过证据。

3. **保护必须直传的信息。** 原始输入、规程、固定约束、布局、当前待修改源码、允许修改对象、全部待验证事项、未解决问题及能力契约不会被字节截断。检查编号、状态、覆盖范围、已知失败及缺口保留完整索引。依赖资产的清单、实际接口、单位、构型、位置、版本、来源要求保持完整；大块部件几何详情改用只读引用。

4. **无损接口表。** 重复接口行的字段名只写一次，记录值按列排列；嵌套值、空值、坐标和单位不变。编解码测试验证还原后的数据等于原输入，包括与编码保留字段重名的输入。失败请求回放另行验证依赖清单、接口与位置数据无损，没有用减少验收条件换取空间。

5. **可执行的详情读取。** `context_read`（上下文详情读取）支持本次输入范围内的引用、字段路径、列表分页和字符串分页。摘要不是已经读取的证据。每页按实际剩余额度缩小，下一页偏移准确保留；原始资料不变。默认每个逻辑任务最多 8 次读取请求，再返回任务结果；所有模型调用共享原账本、次数和令牌预算。成功读取的同一页重复请求会停止，避免无进展消耗；需要跨页保留信息时使用工作笔记。

6. **预算诊断与本地恢复。** 保存请求前后分项、原文绑定、图片标签、读取回执和服务报告用量。超限时只整理可折叠部分，直至落入预算或明确证明必要内容仍不能容纳。没有上调 922,000 的保护阈值、16,000 的输出预留或 32,768 的安全余量。估算仍是文本字节数加每张图 16,384 的工程额度，并非精确分词计数。

7. **视觉和恢复边界。** 只合并像素数据完全相同的图片，同时保留全部来源标签；没有删除不同图片、裁图或降低分辨率。未知已发送请求继续阻断未经显式授权的重试；压缩、读取详情和缓存恢复不重置账本。已保存响应可以通过相同请求缓存恢复，不重复付费调用。

原文、分项回执位于各运行的 `request_context/<输入绑定>/`（请求上下文归档目录）。引用检查范围及内容摘要，不能跨请求任意读取磁盘文件。

## 两轮工程自审

第一轮检查请求契约、提示与异常路径：
- 用实际调用路径确认场景修复和夹具作者绕过旧投影。
- 修正通用折叠可能隐藏全部待验证编号、依赖接口与装配姿态的问题。
- 为所有生成阶段接入同一管理入口，保留最后一次格式错误及原文。
- 原回归中两处旧预期更新为验证“最新反馈完整”和“重复像素合并后两个来源标签仍在”，没有删除这两项行为覆盖。

第二轮检查证据、预算和恢复边界：
- 详情页按真实剩余额度分页，包含笔记和读取索引的开销。
- 补齐跨页工作状态；明确其不是检查器证据，避免只保留最新页后失去前页信息。
- 验证未知请求、次数耗尽、暂停、响应缓存、跨输入引用及原文篡改。
- 扩展现有离线证据流程升级工具的允许文件范围，支持新增上下文模块，并继承新配置默认值；旧资产与账本保留，旧质量结论重新验证，原暂停标志不自动清除。

## 旧运行与未验证项

旧批次和模型来源保持不变。本次代码与配置改变实现身份，不能对旧运行直接换源码后继续发送请求。现有 `prepare_scene_continuation.py --kind evidence_pipeline`（离线证据流程升级）已支持此次改动；它创建保留证据的副本并要求复验，不重置消耗。本次只验证升级行为，没有创建或启动正式接续批次。

本次证明了四个原始失败请求能在保留必要资料的情况下构造到原预算内，也验证了管理与恢复协议。尚未用真实服务验证模型是否能正确使用无损表、按需读取和工作笔记，更未证明场景能够最终通过质量验收。

必要约束、当前源码或全部不同图片本身超过预算时，系统仍会明确停止；没有实现自动拆分任意建模任务，也没有通过删除视觉证据或盲目截断源码强行继续。详情读取可能增加调用次数，因此减少单次上下文不等于保证累计费用降低。服务商真实分词与图片额度仍需后续对照，不声称当前估算精确。
