# 选定流程的任务资料准备

新增 `prepare`（任务资料准备）入口：理解完整规程，选择一条流程，确定准备边界、初终态、资产类型、实例角色及交互要求，再检索参考资料。工作流契约为 `asset_workflow_v3`（第三版资产工作流），公开资料结构为 `2.0`（第二版）。旧全文提取入口和第一版资料仍保留。

本轮只有工程实现与离线验证，没有付费请求、旧实验续跑或基准/评分资料修改。后续真实实验由用户执行。

## 输入与边界

- 必需输入是 PDF（便携式文档格式）规程和运行名称。默认读取当前项目 `config/default.json`（模型配置）及 `config/scene_environment.json`（公开环境配置），可分别用 `--config`（指定配置）和 `--public-environment`（指定环境）覆盖。不继承旧实验预算。
- XML（可扩展标记语言）不会仅因提供路径就全文读取。必须同时指定 `--xml-reason`（缺口原因）及一个或多个 `--xml-query`（补证检索词）才定向补证；冲突以 PDF 为准。当前没有自动发现缺口后重新打开 XML 的工具循环。
- 模型先完成全文索引，再逐页比较候选。按核心目的和依赖完整性、主流程/典型示例、初终态清晰程度、原文顺序选择，不以资产少或操作简单为由缩减目标。文章开头只有出版信息时允许暂不选流程。
- 试剂配制、样本来源准备及非目标材料制作默认提前完成；所选流程的搬运、开合、移液、混合、装卸和设备操作保留。试剂作为容器内容或状态，不生成化学品资产。
- 布局、夹具几何、动作和实际仿真检测器交给下游。图片只检索、下载和记录来源，不做模型看图验证。
- 对外说明默认英文，引文保留原文；命令行和工程说明为中文。网页原始内容及既有模块的部分诊断消息可能保持原语言。

## 命令

先做离线预检，不加载凭据或发网络请求：

```powershell
Set-Location D:\harness\new_harness
.\run.ps1 prepare --pdf D:\harness\selected50_protocols\NP-001\source.pdf --public-environment D:\harness\selected50_protocols\_evaluation\generation_environment.json --run np001_prepare_check_01 --preflight
```

查看该运行的 `preflight.json`（预检报告），确认实际模型、范围、环境和预算。预检与正式运行使用不同名称。

下面的命令**供用户后续执行，会调用付费模型**。300 次调用、1200 万保守词元及 64 次检索是建议停止上限，不是实际费用或保证完成的额度；本轮没有执行这些命令。

仅完成任务和资产需求，包括语义审查：

```powershell
.\run.ps1 prepare --pdf D:\harness\selected50_protocols\NP-001\source.pdf --public-environment D:\harness\selected50_protocols\_evaluation\generation_environment.json --run np001_prepare_task_01 --requirements-only --max-model-calls 300 --max-reserved-tokens 12000000 --max-search-calls 64
```

从新运行完成需求和参考资料：

```powershell
.\run.ps1 prepare --pdf D:\harness\selected50_protocols\NP-001\source.pdf --public-environment D:\harness\selected50_protocols\_evaluation\generation_environment.json --run np001_prepare_full_01 --max-model-calls 300 --max-reserved-tokens 12000000 --max-search-calls 64
```

`--requirements-only`（仅需求）仍会调用模型。完成后可用同一输入、配置和运行名，去掉此参数并增加 `--resume`（恢复）继续参考准备；旧需求交付版本不变。中断恢复也沿用相同命令加恢复参数，累计预算不清零。只有核对服务商记录后，才为结果不明的请求增加 `--retry-uncertain`（重试不明请求）。

旧全文提取账本不能作为第三版恢复输入。规程、范围、环境或代码变化应使用新运行；当前第三版没有跨实现版本自动迁移。

## 持久化、修订和参考准备

状态链为：全文索引、流程选择、任务定义、源文审查、资产登记、角色分配、交互整理、参考检索、交付审查、发布。每段保存来源范围、候选和进度。过长索引响应可细分原文；其他过大请求明确停止并保存状态，不截断目标或证据。

任务修订保存前后摘要、理由和受影响标识；源文审查及交付审查返回局部变更。语义修订与服务格式修复分别记录。必要资产可以补充；重复或范围外资产的撤销必须提供来源依据、保留类型或排除理由，并同步修正角色与关系。产品难找不能用来删除任务操作或降低终态。

资产登记复用已有的候选持久化、身份分页、字段合并和增量提交。同类几何可有多个角色，同一个语义对象不能重复分配；类型数量由角色汇总，不累加跨段提及。未知数量需有推断依据。

`state.json`（内部运行状态）和响应使用同一账本。`progress.json`（进度摘要）给出阶段、已读/未读块、修订号、类型数、实例数、资料缺口与预算。检索前写出 `reference_budget_plan.json`（参考阶段预算计划），不足即暂停，不自动增加额度。

参考按类型准备；目标规格与产品事实分开，保留未知尺寸和适配要求。相同查询、页面及图片地址复用已保存响应；图片按内容摘要保存。不同地址的图片在下载后才可判断内容是否相同。

联网工具明确不受支持时记录一次运行能力缺口，后续类型不重复探测。凭据缺失/无效、服务拒绝、预算耗尽或请求结果未知时停止网络调用。单个产品页面或图片失败仅影响对应参考资料。

## 公开交付与下游

运行返回独立交付路径，并写 `delivery.json`（交付指针）：

```text
runs/<运行名>/deliveries/<内容摘要>/
  input_manifest.json
  asset_package.json
  public_environment.json
  README.md
  images/
```

`input_manifest.json`（输入清单）类型为 `prepared_task_input`（自主准备任务输入）、版本为 2，使用独立加载器，不放宽人工基准白名单。

`asset_package.json`（资产资料包）是该交付版本的权威结果；`README.md`（人工说明）由它导出。运行根目录的同名文件是最近发布结果的副本，下游应使用独立目录中的文件。交付文件、图片与公开环境均验证摘要，已发布版本不能覆盖。

公开包包含任务定义/修订号/摘要、类型、实例角色、交互/配合/辅助要求、公开环境快照、追溯关系和资料缺口。来源只保留实际引用摘录，并记录原来源标识与字符范围。内部候选、审查记录、请求响应和预算账本不进入公开包或模型输入清单。

- 单资产生成读取选中资产及相关角色、阶段、配合对象规格摘要和机器人约束，不重复发送完整登记表。
- 场景生成读取完整任务，必须输出 `role_bindings`（角色到实例映射）。验证数量、类型和对象独立性；后续修复仍保留映射。
- 操作入口核验同一环境及角色映射。编译保存 `upstream_coverage.json`（上游覆盖表），逐项映射语义阶段、初态对象和终态。无法落实的要求进入未核实项，不能以空映射删除。

共享环境适配接受 `workspace_design`（工作区设计）及旧 `workspace`（工作区），不修改公开原文件或原摘要。人工基准仍直接进入生成流程，不调用本模块。

交付后进行场景离线预检：

```powershell
$runRoot = 'D:\harness\new_harness\runs\np001_prepare_full_01'
$delivery = Join-Path $runRoot (Get-Content (Join-Path $runRoot 'delivery.json') -Raw | ConvertFrom-Json).directory
.\run.ps1 scene --package (Join-Path $delivery 'asset_package.json') --run scene_prepared_np001_check_01
```

单资产入口使用同一公开包和实际资产标识；操作入口的任务目录使用该交付目录，公开环境使用其中的 `public_environment.json`。其余执行权限、预算与实现摘要核验遵循各入口文档。

## 状态及验收边界

| 状态 | 含义 |
| --- | --- |
| `requirements_completed`（需求已完成） | 任务、资产、角色、关系与审查完成；未做检索 |
| `completed`（资料完成） | 需求完整，参考准备未报告缺口 |
| `completed_with_gaps`（带参考缺口完成） | 需求完整，有图片、产品或规格缺口 |
| `paused`（暂停） | 预算、服务或用户中断，保留进度 |
| `needs_review`（需要处理） | 结构、语义或修订未通过，不发布新完整版本 |

模型审查不是实际规格、科学有效性或机器人操作证明。当前使用 PDF 可提取文本，不认证扫描图片及表格版式。未完成需求只能作为内部草稿。
