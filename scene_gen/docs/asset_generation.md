# 单资产生成闭环：第一版实现与边界

本模块实现“完整资料 → 模型建模脚本 → 构建 → 独立工程检查及视觉审查 → 局部补丁”。模型保留程序化几何设计自由。框架管理输入范围、产物接口、权限、预算和版本。完整实验台调度与装配现由[场景生成模块](scene_generation.md)提供，任务轨迹仍由后续模块负责。

2026-10-13 新增 `--backend local`（本地执行后端）：使用已有项目环境的独立进程，无需容器；真实工程构建、检查及整场景渲染通过。本地模式不隔离宿主文件或网络，产物大小在导出前检查；日志和超时仍受控。省略该参数保留默认容器行为，恢复时不得切换后端。首次完整场景命令见[静态实验指南](static_preview.md)。

现有 `src/asset_prep`（资产提取模块）源码未改动。生成模块复用其中的服务配置、凭据读取、网络传输、请求账本与进程锁。没有从旧项目迁入代码。

生成、局部修复和视觉审查均使用 GPUGeek（模型接口服务）中的 `GPT-6-astra`（模型标识），默认读取 `config/default.json`（服务配置），请求地址为 `https://api.gpugeek.com/v1/chat/completions`。没有隐式服务切换或备用模型；账本分别保留请求模型和服务返回的模型标识。接口兼容性仍需正式调用验证。

**评测基准直接使用完整资料包和图片，跳过资产提取与联网检索。**复用公共工程工具不代表调用第一模块。读取提取输出的适配器仅为后续仅有原始流程的测试路线预留；完整资料包路线没有任何隐式提取或搜索调用，闭环测试中通过禁止这两个入口的断言验证。

## 已实现

- 两种输入：修订的 Markdown（标记文本）资料包；提取模块的 `asset_package.json`（资产资料包）。后者只接受提取已完成或资料准备完成的状态，保留缺口与配合关系。
- 使用 `--asset`（资产编号）明确选择一个资产或紧密配合组；修订资料包保留全文上下文，只加载所选段落明确引用的图片。不会扫描并提交整个图片目录。
- 图片内容核实、相对路径检查、内容摘要，实际图像像素进入模型请求；没有默默丢弃或缩小参考图。超出配置上限明确拒绝。
- 模型只维护 `model.py`（建模脚本）。首次返回完整脚本，修复只接受唯一文本匹配的替换补丁；不能提交其他文件或修改输入、验收配置。
- 构建与检查使用两个独立 Docker（容器隔离工具）容器；无网络、无凭据、只读挂载代码/输入，限制内存、进程数、运行时间和产物数量/大小。不存在自动宿主执行回退。
- 实际 MuJoCo（物理仿真引擎）编译与引用检查、默认姿态几何包络测量、关节类型和范围核对、初始接触穿透、逐关节7点采样、短时数值检查、多视角及有限关节末端姿态渲染。
- 使用相同服务模型的新审查上下文比较参考资料与实际渲染；这是模型审查意见，不是独立物理证明。
- 接触与位移共同触发按钮事件；只接受框架指定的操作工具碰撞体，避免外壳自接触冒充按压。支持按下/松开阈值及一次性连接释放记录。
- 普通关节直接使用原生模型表达；可拆连接采用具备自由运动能力的组件和可释放等式约束。预分段裁切可复用不可逆释放标记，但完整刀具接触检测尚未接入。
- 有界迭代、先记账再请求、成功响应缓存、恢复、未知请求显式重试、模型身份与用量记录、输入/源码/镜像/产物摘要失效检查。

## 当前限制

“候选就绪”只表示已列工程检查及本次视觉审查没有待修复问题，不代表尺寸、机构、支撑、操作或实验全部通过。

- 未自动将原始资料的所有尺寸转换成可信的量测项；显式数值验收配置支持实际几何尺寸和关节限制，其余要求保留原文并参与视觉审查，不能假称全部得到数值验证。
- 尺寸检查是指定几何在默认姿态下沿世界轴的外包络，不是孔径、内腔容积或公差配合测量。不同测量需求后续增加对应检查器。
- 接触检查遵守引擎碰撞过滤，不能证明静态几何之间、被过滤的碰撞对之间或连续运动路径中完全无交叠。没有全局视觉与碰撞网格一致性证明。
- 短时动力学检查只验证有限数值和引擎警告，不把“没有数值发散”称作“支撑稳定”。
- 含按钮的候选会执行框架压头的真实接触探测，检查事件与连接释放；这是有限压头测试，不等于机器人完成按压。按钮触发方向约定为关节正方向。
- 可拆连接支持显式接合事件和两个定位坐标，实际位置与朝向进入容差后才重新锁合。`irreversible`（不可逆标记）禁止重新接合。复合压旋、螺纹、锁扣的完整弹性力学和裁切刀具接触检测仍未通用实现。
- 刚体替代柔性要在 `approximations`（近似列表）明确记录；不会修改资料原文或声称验证柔性效果。
- 单资产入口的多资产编号只表示联合生成同一组件组；完整场景请使用场景入口。它新增跨资产调度、固定机器人装配、操作装置生成、场景检查与修复；动作规划及轨迹数据导出不在当前模块内。
- 暂无独立的长期支持工具协议、人工审核界面或大规模批处理调度。服务输出采用结构化文本，不依赖第三方函数调用接口。
- 本机容器服务及镜像已就绪，三个资产的实际容器检查通过，整场景回传尚未通过；本地后端完整工程自检通过。正式模型请求与生成质量仍未验证。

## 输出接口

脚本定义 `build(output_dir)`（构建函数），仅向传入目录写入：

- `model.xml`（MJCF，多关节模型描述文件）：弧度、米/千克/秒，+Z向上，不自行生成全局地面和机器人。
- `interfaces.json`（交互清单）：版本、资产编号、语义部件、操作接口、假设、近似、按钮与连接。
- 相对路径网格/材质/纹理文件：不允许外部引用、包含文件、插件或可执行产物。

交互清单的完整格式直接定义在 `src/asset_generation/prompts.py`（提示与交付约定）中，由 `checks.py`（独立检查器）核对实际引擎对象。每个接口绑定部件和局部 `site`（操作坐标标记）。物理实例与完整场景的统一管理留给下一里程碑。

模型在隔离环境中可使用 Python（编程语言）标准库、NumPy（数值库）、MuJoCo、Pillow（图片库）和 trimesh（三维网格库）。目前不提供 Blender（三维建模软件）的程序接口。几何库的可选布尔引擎等依赖也未默认安装；不能假设任意第三方包可用。

## 配置与运行

工作目录为 `D:\harness\new_harness`。正式服务使用已有 `config/default.json`（服务配置）和 `.env.local`（本地凭据文件），不创建或迁移密钥。生成配置在 `config/generation.json`（生成预算与构建限制）。

离线预检由助手或用户执行；不读取凭据，不发模型请求，也不执行生成代码：

```powershell
Set-Location D:\harness\new_harness
.\run.ps1 generate --package D:\harness\selected50_protocols\NP-001\asset_package.md --asset A17 --run asset_input_check_01
```

预期得到 `runs/asset_input_check_01/preflight.json`（预检报告），包括选定资产、图片摘要、输入警告及隔离环境是否可用。预检和正式执行使用不同运行名称。

接入资产提取输出只需替换 `--package` 指向原运行目录的资料包，`--asset` 使用该资料包实际编号。不会重新读取流程或再次调用资产提取。

仅选择容器后端时需要工作镜像。Windows（操作系统）需要可用的 Linux（操作系统）容器后端；本机安装与磁盘位置已配置在 D 盘。显式本地模式跳过此步骤。

```powershell
docker build -f containers/asset-worker.Dockerfile -t harness-asset-worker:0.1 containers
```

构建上下文仅为 `containers`（容器定义目录），不上传仓库凭据和输入。构建镜像时需要下载依赖；运行生成代码时网络被关闭。正式运行前固定镜像；镜像摘要变化会使旧运行失效。

正式模型实验由用户执行：

```powershell
.\run.ps1 generate --package D:\harness\selected50_protocols\NP-001\asset_package.md --asset A17 --run asset_generation_01 --execute
```

实验阶段默认最多10次构建尝试（首次生成包含在内）、40次模型请求（生成与视觉审查合计），累计4,000,000估算令牌占用，单次输出上限16,000。图片令牌采用每张16,384的工程预留，不能证明服务真实计费上限；返回后按预留与报告用量较大者记账。无任何自动扩大预算。

每次隔离构建/检查默认120秒；单资产最多128个普通产物文件、合计64,000,000字节；模型上下文含原图和渲染图，序列化请求上限24,000,000字节。超限需要调整资产组或由用户修改配置。

只读数值验收通过 `--checks`（验收配置文件）提供。示例仅说明格式，数值不代表任何真实仪器：

```json
{
  "dimensions": [
    {"id": "base_width", "geoms": ["base_geom"], "axis": 0,
     "expected_m": 0.1, "tolerance_m": 0.0001}
  ],
  "required_interfaces": ["press"],
  "joints": [
    {"name": "button_slide", "type": "slide", "range": [0, 0.004], "tolerance": 0.00001}
  ],
  "settle_steps": 100,
  "penetration_tolerance_m": 0.0005
}
```

所有验收参数在运行前固定；模型不能修改配置来通过。未提供尺寸项时，报告明确保留尺寸验证缺口。

## 恢复与结果

运行目录包含输入快照、只读检查快照、原有请求账本、请求记录和 `revisions`（资产版本目录）。每轮保留脚本、构建产物、实际检查、预览和视觉审查；失败版本也是有效证据，不自动删除。

```powershell
.\run.ps1 generate --package D:\harness\selected50_protocols\NP-001\asset_package.md --asset A17 --run asset_generation_01 --execute --resume
```

已成功的响应复用，不重复计费。预算暂停可显式提高 `--max-model-calls`（调用上限）、`--max-reserved-tokens`（估算令牌上限）或 `--max-iterations`（迭代上限）后恢复。未知请求在核对服务记录、接受重复调用风险后才使用 `--retry-uncertain`（重试结果不明请求）。

恢复仅自动清理账本明确标记的未提交构建目录，重新使用已缓存响应构建。已提交版本被修改、输入/检查快照被修改、未归档目录冲突时保留现场并拒绝继续。多文件提交不保证跨断电事务；不可恢复时换新运行名称，不手改摘要。

`result.json`（结果报告）的主要状态：

- `candidate_ready`（候选就绪）：列出的工程检查及视觉审查通过，仍保留未验证项。
- `needs_review`（需要复核）：模型明确表示无法判断，不能自动当作通过。
- `needs_environment`（需要修复环境）：如渲染器失败。
- `repair_budget_exhausted`（修复轮数耗尽）：保留失败证据，不伪造成功。
- `paused`（暂停）：预算、网络或用户中断；账本中保存进度。

退出码0表示预检成功或候选就绪，2表示输入/工程失败，3表示未完成或环境/预算暂停，130表示用户中断。
