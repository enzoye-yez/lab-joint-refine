# 资产提取模块的结构性问题复查

日期：2026-10-13。范围：新项目代码与 `np001_completion_01` 已保存的 47 次响应。只做离线分析和临时副本缓存重放；未执行新模型请求，未修改原运行或功能代码。本记录区分已经验证的事实、设计判断及尚未实施的重构方案。此前按类别筛选索引只缓解当前边界，不应称为完整架构修复。

## 已验证事实

1. 47 次响应的结束原因全部为正常停止。响应内容分为 19 份候选清单、19 份合并决定、1 份引用补丁、8 次明确要求拆分。没有输出长度截断，也没有待确认的网络请求。不能把本轮分段增多解释为输出令牌不足。
2. 待发送的第 48 次请求为 48,237 字节，超过本地 48,000 字节上限；其中已有资产索引 41,011 字节，占约 85%。继续减少候选数无法解决已有索引的增长。
3. 已确认总表为 36 项资产、103 条要求；其合并索引 38,593 字节，其中依据说明字符串约 10,517 字节。单个对象最多 14 条要求，其余绝大部分只有 1–5 条。现有数据不能支持“某个异常巨大对象导致失败”的解释。
4. 提取同样携带全局规格索引。两个片段各只有 1 个字符，却分别形成 19,955、25,553 字节请求，已有索引分别占 14,239、19,378 字节。它们均没有提取出资产。
5. 拆分实现将长度取整除以二后作为固定切片步长。例如 1,677 字符变成 838、838、1；453 字符变成 226、226、1。这是单字符碎片的确定性来源，不是 PDF 缺页或模型漏读。
6. 有一段经历 3,631 → 1,815 → 907 → 453 → 226 字符的连续拆分；每次父请求都返回拆分信号。8 次拆分信号调用的服务报告总用量合计 44,537 令牌，包含输入及输出，不等于货币账单，也不能全部视为可避免费用。

## 根因及因果关系

### 全局数据被直接用作每次模型调用的上下文

`extraction.asset_index` 把全部资产及规格送入每段提取；`incremental.compact` 只移除了原文引文，仍携带所有规格和依据，并在每次合并发送全部对象。数据总表、身份检索视图和字段比较输入没有分开。

因此，在单项候选大小不变时，请求仍随全部历史资产及要求增长。将输出改为增量决定没有改变这一输入复杂度；提高字节上限只能推迟失败，按类别分组也只减小常数，同一类别继续增多仍会失败。

### 身份判断与字段合并没有分层

模型在一个操作中同时回答“对应哪个已有对象”和“数量、规格该取哪一方”。为了回答后者，代码把所有可能目标的完整字段提前放入请求。应该先确定身份，随后只比较选定对象的有关字段。

类别是模型生成的分类，跨类别拒绝是当前实现约束，并非已证明完备的物体身份判据。类别筛选不能独立证明真实去重质量，分类不一致的语义风险仍需评估。

### 分段策略把内容密度问题转换成反复切文本

每次最多 8 项候选是工程选择，并非用户研究约束。超过时仅返回拆分信号，父请求不产生可提交候选，再把文本机械切小。仪器清单的条目密度很高，减半字符数不等于合理划分条目；带着全局索引反复请求，会进一步放大费用。整数切片还制造了没有独立语境的 1 字符尾片。

应当区分文档结构、候选分页、响应截断和原子内容过大，不能全部使用同一种文本二分策略。不能通过直接删除短片段来处理，因为短数字或单位可能有语义。

### 恢复依赖重新执行历史控制流程

当前资料包保存总表及进度统计，账本保存请求响应；动态待处理队列和当前段的合并事务没有成为独立、完整的持久化状态。重放可以恢复这次运行，但当提示、分段、索引构造改变时，请求摘要随之改变，所以必须不断增加特定源码版本的恢复适配。

这不是本次 48,000 字节错误的直接原因，却是每次修改后恢复困难的结构性原因。不能把“改代码后要求重跑”作为长期运行模型。

## 重构方案：先定义职责和数据边界

流程应分为：文档结构块 → 局部候选事实 → 身份解析 → 已选对象的字段合并 → 单一资产登记表提交。

- 文档层保留来源、原文区间、章节及邻接上下文，按段落、表格行或材料条目形成任务。处理尾片时并入相邻语境并保留全部字符，不产生独立单字符任务。
- 提取层输出当前块中的候选事实及证据，不携带整份历史规格库，也不负责最终全局资产标识。资料不足形成待决事实，不提前声称全局数量已经一致。
- 身份解析层访问独立资产索引，先确定已有标识或新对象。请求按预算分页；若使用检索缩小范围，必须记录召回范围、未覆盖部分和扩展规则，不能把前几个相似结果当作完整去重证明。新增对象不能仅因为首批结果未命中就立即提交。
- 字段合并层只处理已确定目标与当前候选。完全相同的字段与证据可本地合并；原文来源优先级由代码执行；需要语义判断的冲突才交给模型。字段量继续增加时分页处理字段，不重新塞入其他资产。
- 状态层持久化任务标识、来源区间、待处理队列、局部候选、身份决定、字段决定和提交修订号。结果文件仍是唯一总表；步骤、关系、原始证据及已占用预算保留。恢复依赖明确任务状态，原始请求记录继续用于审计与可复用计算。

这是一项有接口变更的重构，不能再表现为往现有超限分支增加另一个筛选条件。执行顺序应为先固定状态及操作接口，再替换身份解析和字段合并，再调整提取与文档分页，最后迁移历史任务。历史 47 次响应作为不可变证据保留；哪些可直接复用、哪些语义操作需要重做，应逐项说明，不能在尚未验证时承诺全部零新增调用。

## 必须先满足的工程验收条件

1. 使用 10、100、1,000 项合成资产，分别覆盖混合类别与全部同类场景：单次身份及字段请求有明确边界，资产数增加主要增加分页任务数，不推高某个无限增长的请求。
2. 新片段正文相同而历史资产数增长时，局部事实提取的输入大小不随全局规格库增长。
3. 针对真实拆分长度 1,677、453 等检查字符和来源偏移覆盖：无遗漏、无多计、无独立尾部单字符任务；完整段落本身很短时保留邻接语境，不直接丢弃。
4. 同一器具跨段重复提及、别名变化、规格冲突和分类不一致时，身份与字段处理可单独检查；规格证据不因压缩请求丢失。
5. 在每个模型操作和提交边界中断恢复，已确认资产不回退、不重复计数，不依靠模型重新生成已提交清单。
6. 在历史运行副本上验证迁移，保持原始响应、总表和预算；报告新旧操作对应关系，不能以改摘要冒充兼容。
7. 本地验证通过后才请用户进行新的付费实验；测试数量本身不证明架构可扩展或语义完整。

本轮结论：直接阻断来自索引增长；更深层的问题是全局状态与单次模型工作单元没有分离，并且恢复状态仍依赖历史执行路径。前述方案尚未实施，不将文档分析或已有局部修复表述为已经完成结构重构。
